This document defines the **objective criteria the platform is measured against throughout the build and in operation, executed by evaluation agents that take no part in building it.** Every criterion is machine-checkable: a defined method, a numeric threshold, a cadence, and a failure action. Nothing here is satisfied by assertion.

---

## 1. Independence protocol

The evaluation function is structurally separated from the build function:

1. **Separate pool.** Evaluation agents are distinct from build agents ([DELIVERY.md §3](DELIVERY.md)). An agent that has written or reviewed-into-merge any product code is permanently ineligible to evaluate the criteria touching that code.
2. **Separate environment and credentials.** Evaluation agents run from their own workspace with **read-only** access to production metrics, logs, and the research mart, plus one write capability: injecting **synthetic participants** (built on the [TECHNICAL.md §T3.3](TECHNICAL.md) generator) to exercise drills end-to-end. They hold no deploy rights and no identified-tier write access.
3. **Fixed thresholds.** The thresholds in this document are the measuring stick. Build agents cannot edit this file; changes require sign-off from both partners (Sleeptopia and The Mattress Hub) with the change and rationale recorded in the changelog.
4. **Evidence, not summaries.** Every evaluation run emits a signed report — criterion IDs, raw measured values, pass/fail, query/drill transcripts — committed to an append-only audit log. A criterion without an evidence artifact is scored **fail**, not "pending."
5. **Findings route to humans.** Failures file as issues assigned to Ben and the responsible engineer; gate failures (§3) block the gate until re-run passes.

## 2. Scoring

- **Gate reviews (§3)** are pass/fail. A phase does not exit until its gate passes in full.
- **Continuous criteria (§4)** produce a quarterly **scorecard** rating each §3.5 capability red/amber/green: green = all its criteria pass; amber = any criterion within 10% of threshold or one isolated failure; red = sustained or multiple failures. The scorecard is the quarterly review SPEC §3.5 calls for, generated by agents, read by the partners.

## 3. Gate reviews (per DELIVERY.md phase exits)

Run by evaluation agents as checklist audits with evidence attached; every item verified against artifacts, none against testimony.

| Gate | When | Must verify |
|---|---|---|
| **G0 — Legal foundation** | End of P0 (~M3) | IRB approval letter on file; final Lane A/B/C instruments match the IRB-approved versions byte-for-byte; executed BAAs cover every vendor in the [TECHNICAL.md §T3.1](TECHNICAL.md) service list; DUA template counsel-approved; CPAP vendor terms resolved or fallback formally invoked; PRO licenses on file for every instrument in SPEC §5.6 |
| **G1 — Clinic launch readiness** | Before first real enrollee (~M4) | All C-series criteria pass on synthetic participants; revocation drill (C2) passes 5/5 consecutive runs; App Store build matches audited source; coach-portal access model matches [TECHNICAL.md §T3.5](TECHNICAL.md); breach runbook tabletop completed and logged |
| **G2 — Retail launch readiness** | Before first retail enrollee (~M6) | Lane B consent flow renders the counsel-approved text verbatim; SKU catalog validates against T2.4 schema; STOP-BANG scoring verified against published scoring rules on a 50-case test vector; baseline-window enforcement (D7) demonstrated on synthetic retail enrollees |
| **G3 — Research mart release** | Before first mart release / external access (~M9) | Expert Determination opinion on file and its conditions implemented as passing pipeline tests; R1–R3 pass; external-access workflow exercised end-to-end with a mock requester; mart release manifest complete per T3.6 |
| **G4 — Recommendations launch** | Before rec engine v1 ships (~M12) | Every live recommendation type documented against the SPEC §10.3 non-device-CDS boundary test; recommendation reads verified to touch identified tier only under a current authorization (C1 variant); bias check vs. retail-cohort skew on file; human-in-the-loop path demonstrated for provider-facing output |

## 4. Continuous criteria

### C-series — Compliance (the non-negotiables)

| ID | Criterion | Method | Threshold | Cadence |
|---|---|---|---|---|
| C1 | Consent traceability | Random-sample 500 rows across identified-tier tables; resolve each to a current consent grant covering its `(data_class, use)` per T2.6 | **100%** trace; any miss = red + immediate escalation | Weekly |
| C2 | Revocation drill | Synthetic participant revokes; measure collection stop, quarantine execution, and mart-tombstone flag | Collection stops ≤ 1 sync cycle; quarantine ≤ 24 h; 5/5 runs | Monthly + release-blocking in CI |
| C3 | Identifier leak scan | Pattern-scan (names, emails, phones, MRNs, addresses) over outcomes store, mart, logs, and error traces | **0** findings | Weekly |
| C4 | Access audit | Review identified-tier query log: every query has an actor + purpose tag per T3.5; enumerate break-glass events | 100% purposed; 100% of break-glass events human-reviewed ≤ 72 h | Weekly |
| C5 | Consent-text integrity | Hash-compare consent text served in app against counsel-approved versions | Exact match | Every release |

### D-series — Data quality (thresholds from SPEC §3.5 / §6.5)

| ID | Criterion | Method | Threshold | Cadence |
|---|---|---|---|---|
| D1 | Wearable coverage | % active participants meeting ≥ 14-valid-nights/month | ≥ 80% | Monthly |
| D2 | CPAP telemetry coverage | % CPAP participants with telemetry (therapy_gap counts as data, per §6.5) | ≥ 90% | Monthly |
| D3 | SKU attach rate | % enrolled retail purchases with a validated `mattress_purchase` record | ≥ 95% | Monthly |
| D4 | PRO completion | % due day-90 batteries completed within window | ≥ 60% | Monthly |
| D5 | Ingest latency | % source payloads normalized ≤ 24 h from receipt | ≥ 95% | Weekly |
| D6 | Idempotency/duplicates | Duplicate-session detection across `(participant, source, session_window)` | < 0.5% duplicate rate | Weekly |
| D7 | Baseline capture | % new enrollees with ≥ 14 days pre-intervention data at treatment start | ≥ 70% | Monthly |

### E-series — Engineering health

| ID | Criterion | Method | Threshold | Cadence |
|---|---|---|---|---|
| E1 | CI integrity | Test suite + revocation drill green on main | 100% required checks | Every merge |
| E2 | Ingestion uptime | Synthetic-probe availability of webhook/upload endpoints | ≥ 99.5% monthly | Continuous |
| E3 | App stability | Crash-free session rate (both platforms) | ≥ 99% | Weekly |
| E4 | Security posture | Dependency CVE scan + IaC policy checks (encryption, public-access, logging rules) | 0 critical/high older than 7 days | Weekly |
| E5 | Environment hygiene | Scan staging/dev for real-participant data signatures | 0 findings | Weekly |

### R-series — Research readiness

| ID | Criterion | Method | Threshold | Cadence |
|---|---|---|---|---|
| R1 | Mart reproducibility | Rebuild mart from pinned snapshot + pipeline version; compare content hash | Identical | Every mart release |
| R2 | Re-identification red team | Independent agent runs linkage attacks (public-record joins, quasi-identifier combos) against a mart sample | Success rate below the Expert Determination risk bound; findings to ED firm | Every mart release + semiannual |
| R3 | OMOP conformance | OHDSI-style data-quality checks (conformance, completeness, plausibility) | ≥ 95% checks pass, 0 conformance failures | Every mart release |
| R4 | SAP discipline | Verify each sub-study's SAP hash predates its data lock | 100% | Per analysis |
| R5 | Position-data validity | Instrumented-cohort sensor position vs. HST position channel at baseline (calibration per §5.4) | Agreement stats reported and within SAP-declared bounds | Quarterly |

## 5. Reporting

- **Weekly**: C/D/E automated run report to Ben + engineering.
- **Per release / mart release**: gate-style report (C5, E1, R1–R3) attached to the release manifest.
- **Quarterly**: the scorecard — every criterion's value and trend, red/amber/green per §3.5 capability, plus the evaluation agents' list of *unmeasured risks* (things they could not verify and why). The unmeasured-risks list is mandatory: silence about a gap counts as a finding.
